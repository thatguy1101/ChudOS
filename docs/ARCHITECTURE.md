# Architecture

ChudOS = Arch Linux packages + KDE Plasma + a small set of ChudOS packages + an Archiso profile.
No custom kernel, no custom desktop, no custom package manager.

## Layout
| Path | Purpose |
|---|---|
| `distro/archiso/` | Archiso profile. Fields follow upstream `releng`. Placeholders `@CHUDOS_VERSION@`, `@CHUDOS_REPO@` are filled by `stage_profile.py` |
| `distro/archiso/airootfs/` | **Live-only** overlay (live user, autologin, passwordless sudo, installer shortcut, terminal autologin, mirrorlist, bundled package repo) |
| `distro/packages/*.txt` | `base` + `desktop` = installed system intent; `live-only` = live medium only |
| `system/defaults/` | **Installed + live** defaults, packaged as `chudos-defaults` |
| `applications/chudos-welcome/` | Welcome app source (logic in `state.py`/`actions.py`, Qt only in `app.py`) |
| `packaging/*/PKGBUILD` | Arch packages built from this checkout |
| `branding/` | Logo (SVG), wallpaper package (generated by `tools/development/render_wallpaper.py`) |
| `tools/build-iso`, `tools/validation` | Build driver, staging, static validator |

## Live vs installed separation
The live overlay is never packaged. `validate.py` fails if sudoers/autologin/installer-launcher files
appear in `system/defaults/`. The live user's home is seeded from `/etc/skel` (via tmpfiles), so live
and installed desktops share one source of defaults.

## Desktop defaults mechanism
Only supported Plasma tools are used. The wallpaper is applied at first login by
`plasma-apply-wallpaperimage`; a marker file is written only after success, so failures retry.
`/etc/skel/.config/kdeglobals` sets `ColorScheme=BreezeDark` for newly created users only.

## Dopamine Profiles (engine: `applications/chudos-profiles`)
`schema.py` (registry of the 5 implemented settings + strict validation) -> `store.py` (JSON files; built-ins from
`/usr/share/chudos/profiles`, user data in `~/.config/chudos/profiles`, active profile in `~/.local/state/chudos`) ->
`apply.py` (reads current values, writes only changed ones through kwriteconfig6/plasma-apply-colorscheme, reloads KWin
over D-Bus, rolls back on failure, file lock against overlap) -> `cli.py` (`chudos-profile`). No daemon, no polling:
it runs only when invoked. Profiles are data only; nothing in them is ever executed.
Settings outside the registry do not exist; adding one requires a read + write + rollback implementation and a test.

## Privileges
- Welcome app runs as the user; it launches fixed argv lists, no shell, no file-supplied commands.
- Live user has passwordless sudo **in the live session only**.
- Build: `makepkg` as a normal user; `mkarchiso` as root.

## Dependencies / trust
Official `core` + `extra` repos with `SigLevel = Required DatabaseOptional`. One extra local repo
`[chudos]` (file://, unsigned, built on the build machine) holds only the two ChudOS packages.
No network repositories beyond Arch mirrors.
